# v1 scope

Status: Accepted (2026-10-10)

## Context

The original SuperSlide ([research](../research/2026-10-10-original-superslide.md)) is valued for speed: images appear instantly and zoom and pan are smooth. Much of the rest is costly to rebuild or risks damaging the owner's files.

## Decision

v1 keeps the fast-viewer core:

- Opening: a file, a folder, or a recursive open, by drag-and-drop, command-line path, O or Shift+O; folder filter.
- Navigation: Space and Backspace, left-click previous and right-click next, under the advance limit; slideshow (A).
- Viewing: fit, zoom, pan, fullscreen (F11 or Enter, Esc to leave), screen rotation (R, L), info overlay (I), magnification filter toggle (Ctrl+F) for sharp pixels at high zoom.
- Ordering: sort modes N, D, Z, S, V reverse, group by subfolder (G) with Ctrl+Left/Right.
- File actions: delete to the Recycle Bin, move, copy; Ctrl+C copies the current image, Ctrl+V views a clipboard image.
- Preferences screen (P) and session restore, both stored beside the executable so a copied folder carries them, as the original's flash-drive use did.
- Formats: JPG, PNG, TGA, BMP.

v1 cuts:

| Cut | Why |
| --- | --- |
| Transitions | Hard cuts are enough for the owner; transitions were the largest creative and shader effort. |
| Writing rotation to EXIF | Editing JPEG metadata in place can corrupt files; screen rotation covers viewing. |
| Fast-forward and fast-back | Full decodes cannot keep pace with a held key; the advance limit replaces it. |
| File associations and single instance | Windows integration work the owner does not need. |
| Contrast adjustment (t/T) | Rarely used in a viewer. |
| Software render mode | wgpu falls back to WARP on Windows when no suitable GPU exists. |
| ICC colour management, more formats | The original had neither. |

## Consequences

- The viewer writes to image files only through the explicit delete, move and copy actions; screen rotation and every other feature leave files untouched.
- With no transitions, every image change is immediate, so only the preload cache and decode speed govern how fast navigation feels.
- The held-key advance and the slideshow share one timer.
