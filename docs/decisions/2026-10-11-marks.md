# Marks

Status: Accepted (2026-10-11).

## Context

File actions and Ctrl+C worked on one image at a time. The owner's friend asked to mark images, then yank, delete, move or copy them all at once (SSR-26). Design settled with the owner in chat; the keys are in [keymap.md](../context/keymap.md), the behaviour in [architecture.md](../context/architecture.md) *Marks*.

## Decision

- **`m` marks, after nsxiv.** nsxiv, the Vim-keyed image viewer, marks with `m`, so Vim users expect it there. Move left `m` for `x`, Vim's cut. Copy stays on `c`, so only one learned key changed. `M` clears all marks; `n` / `N` go to the next / previous marked image, as Vim's search-next does.
- **No new action keys.** While any image is marked, `dd`, `x`, `c` and `y` act on every marked image instead of the image on screen. With none marked they act as before, so one-image habits keep working. The marks corner keeps the count on screen, so the owner does not forget marks before a bulk delete.
- **`[count]m` takes the current image's opposite state for the whole run**, so a mixed run comes out uniform, as Vim's counts act on a run. It does not move, so the mark shows on the image the owner is looking at.
- **`y` with marks copies files, not pixels.** One clipboard image cannot hold several. A file list (`CF_HDROP`), as Explorer's Ctrl+C makes, pastes into Discord as one upload per image and into a folder as the files. With nothing marked, `y` copies pixels as before, since Paint and image editors cannot paste a file list.
- **Marks belong to files.** Re-sorting and shuffling keep them; a new image list starts with none; the session does not save them.
- **Success unmarks, failure keeps the mark.** A bulk action ends in one notice naming the first failure, and the images that failed stay marked for another try.
- **Vim keymap only.** The classic keymap's M is move. Its Delete, M, C and Ctrl+C still act on marks made in the Vim keymap, since the marked-set logic is shared.

## Consequences

- A bulk action is a `file_actions::domain::Batch`: the file action thread still gets one job per image, and the batch collects their results into one notice.
- `p` after a multi-image `y` finds no image on the clipboard and says so.
- The top-left corner, the last free one, now holds the marks.
